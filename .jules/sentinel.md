## 2024-05-18 - [HIGH] Fix Stored XSS via HTML Escaping
**Vulnerability:** User inputs like profile names (`p.name`) and team member emails (`email`) were being injected directly into the DOM via `innerHTML` without sanitization. This allows for Stored Cross-Site Scripting (XSS) if malicious payloads are saved in local storage.
**Learning:** In vanilla JavaScript applications utilizing template literals with `innerHTML` for rendering, failing to sanitize untrusted user data exposes the application to serious XSS vulnerabilities.
**Prevention:** Always implement and enforce a global HTML escaping utility function (e.g., `app.escapeHtml`) to sanitize any dynamic, user-controlled data before it is rendered to the DOM using `innerHTML`.
## 2024-05-24 - Unsanitized User Inputs in Template Literals
**Vulnerability:** Found multiple instances of Cross-Site Scripting (XSS) vulnerabilities where user inputs (`searchQ`, `s.messages`, and `projectName`) were directly interpolated into DOM elements via template literals without proper sanitization. Additionally, `app.escapeHtml` was not properly handling `undefined` or `null` values correctly, breaking valid edge cases or allowing evasion.
**Learning:** This pattern existed because standard template literals in JavaScript do not automatically escape variables when used to set `innerHTML` or similar DOM properties, allowing arbitrary script execution. The `escapeHtml` function relied on a simple falsy check (`!str`), which did not properly account for explicit `undefined` and `null` string contexts.
**Prevention:** Always wrap variables representing user input with `app.escapeHtml()` when interpolating them into HTML strings via template literals. Ensure `app.escapeHtml()` explicitly checks for `null` and `undefined` instead of generic falsy values to properly handle and escape empty or uninitialized strings safely.
