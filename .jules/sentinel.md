## 2024-05-18 - [HIGH] Fix Stored XSS via HTML Escaping
**Vulnerability:** User inputs like profile names (`p.name`) and team member emails (`email`) were being injected directly into the DOM via `innerHTML` without sanitization. This allows for Stored Cross-Site Scripting (XSS) if malicious payloads are saved in local storage.
**Learning:** In vanilla JavaScript applications utilizing template literals with `innerHTML` for rendering, failing to sanitize untrusted user data exposes the application to serious XSS vulnerabilities.
**Prevention:** Always implement and enforce a global HTML escaping utility function (e.g., `app.escapeHtml`) to sanitize any dynamic, user-controlled data before it is rendered to the DOM using `innerHTML`.

## 2024-05-18 - [CRITICAL] Prevent Stored XSS via Regex Tag Stripping Bypass
**Vulnerability:** The recent messages list preview used `.replace(/<[^>]*>/g, '')` to strip tags from untrusted content. This is brittle and misses malformed tags (e.g. `<img src=x onerror=alert(1) `). Since the stripped content was injected directly via `innerHTML` without HTML escaping, this allowed for Stored Cross-Site Scripting (XSS).
**Learning:** Never rely solely on regex tag stripping to sanitize untrusted input for `innerHTML`. Regex tag strippers are notoriously brittle and prone to bypasses, especially with malformed tags or when combined with string truncation.
**Prevention:** When sanitizing untrusted input, always wrap the output of any regex tag strippers (and string truncations) in a robust HTML escaping function (e.g., `app.escapeHtml()`) before injecting it into the DOM. Always escape after regex/truncation to prevent splitting HTML entities or missing malformed tags converted by escaping.
