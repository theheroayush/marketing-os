## 2024-05-18 - [HIGH] Fix Stored XSS via HTML Escaping
**Vulnerability:** User inputs like profile names (`p.name`) and team member emails (`email`) were being injected directly into the DOM via `innerHTML` without sanitization. This allows for Stored Cross-Site Scripting (XSS) if malicious payloads are saved in local storage.
**Learning:** In vanilla JavaScript applications utilizing template literals with `innerHTML` for rendering, failing to sanitize untrusted user data exposes the application to serious XSS vulnerabilities.
**Prevention:** Always implement and enforce a global HTML escaping utility function (e.g., `app.escapeHtml`) to sanitize any dynamic, user-controlled data before it is rendered to the DOM using `innerHTML`.

## 2026-10-08 - Fix XSS Regex Bypass in HTML Stripper
**Vulnerability:** A regex tag stripper (/<[^>]*>/g) intended to sanitize user messages before injecting them into the DOM failed to account for malformed HTML tags. Since the regex looks for an explicit closing bracket (">"), an attacker could craft an XSS payload using an unclosed tag (e.g., <img src=x onerror=alert(1) ), bypassing the regex and executing malicious code in the browser context.
**Learning:** Naive regex HTML tag stripping is insufficient for neutralizing XSS because browsers parse and attempt to auto-correct malformed tags. When a malformed tag bypasses the regex and is injected into innerHTML, the browser executes the payload.
**Prevention:** Never rely solely on regex for HTML sanitization when using innerHTML. Always apply a robust HTML entity escaper (e.g., app.escapeHtml()) after regex stripping, or use secure rendering alternatives like DOM text nodes, to ensure any unclosed or bypassed tags are safely neutralized.
