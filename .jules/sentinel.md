## 2024-05-18 - [HIGH] Fix Stored XSS via HTML Escaping
**Vulnerability:** User inputs like profile names (`p.name`) and team member emails (`email`) were being injected directly into the DOM via `innerHTML` without sanitization. This allows for Stored Cross-Site Scripting (XSS) if malicious payloads are saved in local storage.
**Learning:** In vanilla JavaScript applications utilizing template literals with `innerHTML` for rendering, failing to sanitize untrusted user data exposes the application to serious XSS vulnerabilities.
**Prevention:** Always implement and enforce a global HTML escaping utility function (e.g., `app.escapeHtml`) to sanitize any dynamic, user-controlled data before it is rendered to the DOM using `innerHTML`.
## 2024-06-10 - Fixed XSS vulnerability in DOM innerHTML assignments
**Vulnerability:** Found a Cross-Site Scripting (XSS) vulnerability where a search query parameter `searchQ` was directly interpolated into the `value` attribute of an HTML input field using `innerHTML` without sanitization. An attacker could inject arbitrary HTML or JavaScript via malicious queries.
**Learning:** In vanilla JavaScript applications using template literals for rendering, any user-controlled input interpolated directly into `innerHTML` is inherently unsafe. The codebase has a global `app.escapeHtml()` utility designed to mitigate this, but it must be manually applied to *every* dynamic string interpolation.
**Prevention:** Always wrap dynamic, user-controlled data in `app.escapeHtml()` (or equivalent sanitization function) before injecting it into DOM templates via `innerHTML`. When using template literals for HTML generation, treat all variables as untrusted by default unless they are statically defined.
