## 2024-06-04 - XSS via Incomplete Regex Stripping and Safe Truncation
**Vulnerability:** The history view in `app.js` relied on a naive regex (`/<[^>]*>/g`) to strip HTML tags from user message previews. This allowed XSS payloads with unclosed tags (e.g., `<img src=x onerror=alert(1) //`) to bypass the filter and execute. Additionally, if the stripped string was truncated *after* HTML escaping, it could chop entities in half.
**Learning:** Naive regex HTML stripping is consistently insecure and easily bypassed. Furthermore, the order of string operations matters: truncating an escaped string can lead to broken entity rendering (e.g., cutting `&quot;` into `&qu`).
**Prevention:** Always wrap potentially malicious user input in a robust HTML entity escaping function (like `app.escapeHtml()`), even after attempting to strip tags. When combining escaping and truncation, always truncate the raw string *before* applying the escape function to prevent malformed entities.
