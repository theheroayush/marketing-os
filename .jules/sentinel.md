## 2024-05-24 - [DOM XSS via Template Literals & Incomplete Escaping]
**Vulnerability:** Found multiple DOM XSS sinks where unescaped string variables (`searchQ`, `projectName`, `p.id`) were interpolated into `innerHTML` strings. Additionally, the `app.escapeHtml` implementation incorrectly dropped valid falsy values (like `0` or `false`) because of an `if (!str)` check, and a preview truncator relied solely on a regex `/<[^>]*>/g` which fails on malformed tags.
**Learning:** Even when an escaping function exists, developers often forget to apply it to every dynamic variable inside large template literals used for rendering. Furthermore, custom sanitization like regex tag stripping is insufficient without full entity encoding.
**Prevention:** Always wrap every dynamic variable in an HTML-escaping function when using template literals for DOM insertion, unless the variable is explicitly known to be safe HTML. Ensure escaping functions strictly check against `null`/`undefined` rather than generic truthiness to avoid data loss.
