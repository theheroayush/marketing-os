## 2024-05-29 - [Refactoring Markdown Parsers for Performance]
**Learning:** [When replacing chained `.replace()` calls with a single-pass regex to improve performance (e.g., in a markdown parser), characters matched inside mutually exclusive capture groups (like bold syntax `\*\*(.*?)\*\*`) bypass other replacement rules (like globally escaping `<` and `>`). This can inadvertently introduce Critical XSS vulnerabilities if user input contains unescaped HTML tags within those specific formats.]
**Action:** [When optimizing string replacements, always ensure security boundaries (like HTML escaping) are applied independently or correctly handled inside the replacement callback for all matched capture groups to prevent XSS regressions. It's safer to optimize pure escaping functions (like `escapeHtml`) than complex syntax parsers.]
