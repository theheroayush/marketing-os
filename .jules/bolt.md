## 2024-06-03 - Optimizing Array Filters with Early Returns and Hoisted Variables
**Learning:** When using `Array.prototype.filter()` with multiple conditions, evaluating all conditions indiscriminately (e.g., `const match1 = ...; const match2 = ...; return match1 && match2;`) is computationally expensive, especially when one condition is cheap (like an exact string/category match) and another is expensive (like `.toLowerCase().includes()`). Furthermore, recalculating loop invariants like `.toLowerCase()` on the search query inside the filter callback forces redundant work for every item in the array.
**Action:** When filtering arrays, always hoist loop invariants (like formatting the search query) outside the `.filter()` callback. Structure the callback using early returns so that inexpensive boolean or exact-match checks are evaluated first. Return immediately if they fail to prevent executing computationally expensive operations (like string allocations for `.toLowerCase()`) on items that will be filtered out anyway.
